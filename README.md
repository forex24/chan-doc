# 缠论规则、原文与 Rust L0

## 当前研究主线：递归与多义性的业务规则

2026-10-05 用户明确研究重点应落在规则。完整F2的首要交付是可构造、可反驳、可逐层复用的业务规则体系，不是接口数量、文档数量或局部数值审查通过次数。已得MACD、冻结、Vec／下标和共享结果保留；除非发现影响业务结论正确性的缺陷，暂不继续扩展这些工程专题作为主线。

- **递归生成：** 明确最低层基础材料与递归走势类型的关系，以及本级如何形成中枢、延伸、完成，再产生可供上一级使用的真实材料。[35课](原文/chzhshch-108-plus/108/0475-486e105c01000914-035.md)允许混合低级连接经合法重组变成次级分解；[84课](原文/chzhshch-108-plus/108/0718-486e105c01000cx4-084.md)区分启始函数与递归函数。不能从现有L0数据结构反推全部业务对象必须是一条L0，也不据此批准新的任意组合材料。
- **合法多义：** 先说明何时产生另一解释、改变哪些分组／角色、保留哪些事实、何时因规则失效。[36课](原文/chzhshch-108-plus/108/0478-486e105c0100093a-036.md)保留不同中枢起点及各自第三类点标准；因此不同解释不是一概等价的证明包装。[38课](原文/chzhshch-108-plus/108/0485-486e105c010009be-038.md)的指定同级分解政策，也不能冒充唯一全局分解。只换括号不自动产生新走势；改变中枢或材料角色的合法重组须保留真实差异。
- **生成与覆盖一起审查：** 每条规则写清实际输入、适用级别／分解、前提的生产来源、确切输出、合法后继与首次成立依据。同时检查错误生成和遗漏合法解释。“有完整c／升级／合法转换证书”只描述消费前提，不等于已经交付这些证书的生产规则。只有同一批事实相互支持而无独立依据时才是循环；不得仅因多个结论同事件成立就拒绝合法的无循环联合推导。

优先重审项目自行增加的限制：固定直属分解、固定窗口／进入位置、九项封闭分配、普通完成与固定H分段之间的推导边界。五类窗口目前是已列出的有限工程入口，不是全部原文重组的完备定理。每项限制须给出原文依据或保持合法解释覆盖的推导；否则保留为待审假设，不让存储或调度便利决定业务真值。

当前主问题合并为一条研究链：**最低层与完整走势的衔接 → 合法分解与重组 → 中枢及走势的延续／完成 → 九段和扩张的真实递归构造 → 新级别继续适用规则。** U09与完整c必须交付实际材料、角色及完成见证，不能用增加缺项名称代替；D03/D04的共享表示服从这条规则链。上述是研究优先级与审查要求，不表示已证明任何新的完成或升级规则。整体设计通过前不写F2源码、测试或演示。
