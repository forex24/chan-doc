- [缠论业务规则总表](缠论业务规则总表.md)：集中整理业务规则，区分原文、项目裁决、工程实现选择与未决问题；末尾附 108 课本地索引。
- [原文副本](原文/chzhshch-108-plus/README.md)：108 课正文、原文件所含问答、图片及原许可证。共 160 个文件，复制时逐文件 SHA256 校验。见 [复制清单](原文/复制校验清单.json)。
- [Rust L0](rust-l0/README.md)：独立维护的 Bar 到 L0 管线，可独立构建和测试。当前使用有限 `f64`、UTC 日期时间和扁平 `LowestMovement`；完整范围来自实际端点间的原始 Bar 闭区间。没有 F2 引擎。
- [Rust F2 集成设计与闭合审查（待评审）](docs/F2设计方案.md)：唯一现行主入口，统一实际生产域、消费者、启动、来源、冻结、共享、动态级别及完整验收。原104KB详细条款按同一Git blob保存在[历史细则](docs/F2设计细则-79f3965.md)，不作为另一份现行主设计。当前工作门禁见 [CONTINUITY](CONTINUITY.md)。

主设计的专题依据：[九段构造核查](docs/F2九段构造核查.md)、[249／324-Bar贯通场景](docs/F2贯通场景.md)、[支持与消费者接口](docs/F2支持与消费者接口.md)、[MACD数值合同](docs/F2MACD数值合同.md)。当前已有有限F6-D／S06高级核心、R32-P普通左完成及G2继续消费的来源明确纸面构造，也有局部物理共享、时间与MACD合同。274-Bar条件业务反例进一步表明固定左移构造不覆盖全部合法九延伸；多L0比较范围与完整c材料权限已分离。以上经过范围复审，尚未作为F1／F2运行验收；通用九段、完整c和整体F2设计仍在继续闭合。

**续轮设计提案：** [冻结截面与同事件归约](docs/F2冻结截面与同事件归约.md)区分同事件内的材料前缀、知识截止和当前活动权；[比较窗口的增量判定](docs/F2比较窗口的增量判定.md)给出闭区间拼接和必含前缀下的有限面积否定，并防止把确认尾算入历史c。各项以其实际复审范围为准，PR #1新增的有限T3测量规则已经自动复核，不等于全部冻结／比较合同或完整F2通过。

**第99课来源转换提案（待独立复审）：** [第99课来源转换](docs/F2第99课来源转换.md)结合91／93／98／99课，区分类形态、局部材料转用与普通完成；明确d/e/f吸收、f/g/h保留两种位置的来源、权限和首次事件，不将类形态包装为新H0，也不重复既有冻结／测量稿。

**本轮集成新增：** 主§3.8区分外部ordinary种子与自动启动，§6.1给出需逐Γ核查的分隔关系算法，§7.4拒绝同事件无根时间方程自证，§9.1—9.2以真实不重复owned见证证明动态层级质量界及有限NoHigher证书。全部新条款仍待独立审查；没有将九项计数恢复为升级算法，没有以无种子规则链的停滞声称市场无转折。

用途是为独立 Rust 开发保留规则、原始依据和可用的 L0 基础。**未决合同仍是未决合同**，不能将文档整理、代码抽取或局部回归通过当成全部缠论规则已解决。

**R4 已有批准规则：** 未知左边界下允许局部结构持续识别与发布，但不自动授予整体完成或升层。[规则总表 §2.5](缠论业务规则总表.md#25-r4未知左边界下的局部能力已批准)可作为 Rust F2 的设计依据，无需等待旧 Dafny 工程全部证明通过；开始实现仍须通过本仓库当前设计门。“旧实现未签收”与“业务规则未确定”分开记录；本目录目前仍只有 L0 代码，没有 F2/R4 实现。
