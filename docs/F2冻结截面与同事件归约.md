**状态：新增工程提案及纸面证明，尚待独立复审。** 本文补充[主设计](F2设计方案.md)的§6—7和[支持接口](F2支持与消费者接口.md)的§9、15—16，不替代唯一主设计，不宣称D05、D03/D04或整体设计已经通过。没有编写、运行F2源码、测试或演示，也没有新F1回放结果。

## 1. 需要补齐的不是一个时间字段

当前[上游delta](../rust-l0/src/lowest.rs)允许单次输入发布有序的多条线段／L0；[贯通场景](F2贯通场景.md)也有q8、q9在同一事件获证的纸面预期。因而输入事件、所见材料前缀和规则处理顺序不是同一个坐标。

现有方案已经区分历史、活动和冻结，并要求不可变事实版本。本提案把这一要求落实到创建位置、谓词及同事件处理：只保存known_at或读取C.latest，不足以实现“在指定材料边界冻结”。反过来，给每份解释复制一份完整历史状态也不是必要条件。

必须分开三个问题：

| 查询 | 实际问题 | 不可替代的内容 |
| --- | --- | --- |
| PrefixState | 指定解释／绑定消费到指定材料后，局部状态是什么 | 有序材料截面、角色及相容状态推导 |
| KnownBy | 这份具体依据在日志事件E结束前是否已经可知 | 同一完整证明的获知事件，不是材料端点UTC |
| ActiveAfterCommit | 完成本次事件全部必要推导后，下一输入由谁接收 | 已获证授权／停止／交接及适用的材料截面 |

前缀状态不是墙钟快照。后来的证据可以让程序首次证明一个旧材料截面的状态；这份证明的known_at仍然较晚。如果规则要求“证据当时已经齐备”，则另加KnownBy截止，不把晚证明倒填到过去。

## 2. 最小反例：同一事件的两个不同材料截面

设指定局部C的核为[2,8]，前状态开放，前材料终点为8。完成资格、来源和角色均作为显式已获证输入。

事件40同时交付：

| 顺序 | 材料 | 该绑定消费后的状态 |
| --- | --- | --- |
| 第一项d | 上向8→12，完整范围[8,12] | AwaitingFirstReturn(up)，离开为d |
| 紧邻第二项r | 下向12→10，完整范围[10,12] | Completed；首返全范围严格高于8 |

两项的首次获知事件都为40，但“d之后”不等于“r之后”。在d处冻结离开／左前缀的消费者，必须引用d之后的截面，不能在队列稍后运行时读取已完成的C.latest，并反称离开时状态已经完成。

这只是获准材料层的接口反例，不是新Bar/F1复现；它不授包含C的普通整体完成。

另一种同类情况是：规定第九项触核且不离开，第十项离开，第十一项严格首返，同一事件发布三项。第九项后的开放状态不能用本事件末的完成状态替换。单个事件编号无法选择这三个截面中的哪一个。

## 3. 用已有转移结果保存截面，不增加全局执行键

本提案使用已有Vec对象和稳定下标。每个真实具名消费请求已经知道前状态、本次材料、角色及结果槽；在成功消费时，结果槽保存一个不可变截面引用。它至少引用：

- 对应的数值状态G或完成／固定请求结果；
- 该截面的实际Reach支持关系，而非未来会被原地改成另一前缀的活动指针；
- 已消费的有序材料片段／原位置以及尚未消费的首个待决输入；
- 适用的数据／规则域与已成立的真实角色；
- 推导支持端口及各充分见证的实际known_at。

这不是把上述字段拼成ObjectKey或ExecutionKey。创建归属于已有消费／冻结结果槽；重复相同请求读取原槽。纯数值G仍可按现有M-owned目录共享，截面的实际绑定留在Reach。多个需要同一截面的Q引用已有节点，不复制整个状态Vec、全部来源数组或所有解释历史。

冻结问题的不同字段可能来自不同的真实截面。例如旧Local29左结构在b离开边界冻结，右开放状态在其指定右窗口边界冻结。Q分别引用它们及实际来源转换，不能为了少存一个引用把二者改成同一事件末快照。

未覆盖、固定重组请求、资料不足均不创建“已成功消费N”的可续截面。保存旧截面与首个N的问题引用，等待该绑定的合法处理。另一解释成功消费同一N，不使本绑定自动前移。

## 4. 冻结有两种不同合同

### 4.1 固定材料域的历史结构

PrefixState(C,p,b)的p是已知的真实材料截面，b包含所需S、来源、角色及残余相关变量。后面更多材料到达不会改变这个查询的材料域。晚到的合法来源证据可支持该历史域，但其首次支持事件取晚到证据参与后的最大值。

一个支持端口可以追加另一份证明；追加不得改变命题中的p或将另一S／另一分段写入同一无条件行。相同位置下确有其他合法绑定时，保留有条件的关系行。

### 4.2 截止事件前已经知道

KnownBy(F,b,E)要求存在一份实际完整支持w，满足w支持F(b)，且e(w)≤E。不能只因F描述的材料都位于旧日期，就判定该证据在E已知。

已完成事件闭包后，KnownBy的过去真值不因未来原始输入改变。若后来发现当时漏注册了一个完全由已知事实可推导的消费者，这是闭包／追赶缺陷，不能把修复后补算伪装成新的业务事实早已被完整发布。

因此，“同一冻结对象后来可补起点证明”和“冻结时起点证据已齐”是两个不同规则前提；每条普通完成规则必须选择自己真正需要的那个。本文不替R29/R32普遍增加或删除这项业务前提。

### 4.3 I/J截止例

保留真实共同绑定：I有P@1、Q@10；J有P@9、Q@2。

| 查询 | 正确结果 |
| --- | --- |
| 无截止的同绑定P∧Q | J@9、I@10；存在性最早9 |
| 截止E=8 | 无完整联合支持；不能用I的P@1与J的Q@2拼成2 |
| 截止E=9 | 只有J@9 |
| 后续只允许I | 最早10；截止9时仍不成立 |

先过滤完整绑定和完整证明，再做合法联合／投影。只保存全局最早9，无法回答“只允许I且截止9”的问题；保存完整历史路径数组也不是唯一正确表示，实际P/Q/I关系端口就足以表达此例。

## 5. 同事件闭包不能由瞬时Active布尔值决定历史事实

考虑事件E内先发现一个旧解释的合法延伸依据，后发现该解释在另一个实际截面应转交高级职责。若历史事实的产生依赖队列读取到的瞬时Active，先执行哪个回调就可能决定某条历史事实有没有被记录。

修正方向是：

1. 历史推导读取明确的PrefixState、资格及具名转换，而不是原地可变的“现在active且尚未看到stop”。
2. 新授权与终止／交接先记录它们的真实对象、作用截面和充分证据；历史事实不被整批删除。
3. 对外的ActiveAfterCommit在必要事件闭包完成后，按适用业务规则计算。不要把先入队者当成胜者。
4. 需要继续生成材料的消费者，必须核验该真实绑定在相应前缀上的消费许可。取消瞬时Active读法不意味着放行已终止解释，或对所有历史分支无条件继续。
5. 若两个结果只是来自合法不同解释，分别保留；若同一实际作用域要求互斥却缺裁决规则，记录该规则冲突／未覆盖，不用队列顺序补出优先级。

对真实停止／交接点落在某个截面之前还是之后，必须由业务来源决定。统一规定“高级永远压低级”或“先处理完全部低级再看高级”都不是这里得到的原文结论。

## 6. 可以证明的归约不变性，以及未证明部分

将本事件内一组已固定作用域的历史规则写成有限正前提推导：每个结论的事件为前提事件max，多份完整证明的候选值取min；所有源事实、材料截面和目标关系不可变，不以暂时缺失另一结论作为成功前提。

在实际可达规则实例及支持域有限、每次语义变化可检测、调度公平的前提下，从相同种子事实反复执行这些规则，得到相同最小闭包；实际处理顺序不会改变其业务事实集合和每个完整绑定的最早支持事件。理由是各步只加入种子可达的充分后果，不删除后果；闭包包含全部可达推导，任何公平顺序最终包含同样结果。纯包装新增不作为语义变化继续自激发。

这项条件证明没有证明F2所有规则实例有限，也没有证明含否定、Active覆盖、任意J/Γ或同级重组的全系统合流。恰恰相反，若一条规则读取“当前还没有停止事实”而后把结果当永久真，以上正前提证明不适用，必须补分层／截止或业务优先级。

已完成同事件多交付应按真实来源次序满足依赖。例如同一D的P4、P5同时获证，P5的可消费前态必须是P4消费后的截面，而不是二者分别从P3出发。数值结果可共享；来源次序与实际权限不能靠交换回调忽略。

## 7. lastZ覆盖后可消去什么

现有支持方案保留lastZ以生成固定重组请求。永久把所有旧lastZ差异装进每个未来状态也不必要。

设F(x,z,ρ)为活跃前缀支持，z是旧lastZ，x/ρ包含其余仍有作用的真实字段。一条经验证的吸收动作对整个所选域都将lastZ替换为同一个实际qualified材料n，动作授权Δ及其余更新不读取旧z，未来该活动消费者也不再读取旧z，则：

`min_z max(F(x,z,ρ), Δ(x,ρ,n)) = max(min_z F(x,z,ρ), Δ(x,ρ,n))`。

因此活动端口可以对旧z投影，新的lastZ为n；不按旧z继续复制共同后缀。该等式只在固定x/ρ及真实共同n下成立。

必须保留的限制：

- 若本次是离开、暂存连接、等待首返，没有获准吸收为有效Z，就没有覆盖旧z的授权。
- 若不同绑定只共享AtomicExport(n)，实际qualified材料／来源映射不同，则保留n(b)或相关关系，不能声称统一覆盖为一个实际材料。
- 覆盖前已经生成的Q或ReassocRequest仍引用旧截面F(x,z,ρ)，其lastZ不得被更新为n。
- 计数、旧组成范围、整体分类或其他未来消费者仍读取的字段保留；只消去真正不再作用于该活动消费者的z。
- 审计证明与指定历史来源查询仍从原见证／截面读取，不因活动投影销毁。

这比“整个解释名字永远不能忘”更弱，也比“用了固定字段就能丢全部历史”更严格。它给出一个具体可逐消费者应用的变量消去位置，不是全域压缩证明。

## 8. 存储与执行规模分开报告

设T为实际不同共享转移数、Q为实际冻结／请求数、R为仅证明包装不同的记录数。在每个截面只保存定长已有引用、纯包装不新增实际绑定、共享后缀满足既有统一转换条件时，截面及证明附加存储可为O(T+Q+R)，而不是为每个Q复制前面T步。

这不自动给任意Q查询O(1)或全部运行O(T+Q+R)。应另报：真实Reach/Γ关系大小、局部首次查找、每个截面查询读取的相关行、KnownBy过滤、权限变化、失败匹配及输出。Q份问题如果确实逐份查询R个不同业务绑定，可能有RQ成本；它们不是R份同一绑定的纯包装。

固定链上纯包装的最早事件已经被端口维护时，KnownBy只需检查该行最早事件≤E。I/J这类不同真实绑定仍须先匹配，不能用这个特例跳过联合。

截面复用沿原消费／问题生成槽取得，不建立以(事件,对象,材料位置)为键的全局快照注册表。暂停、失败撤销和恢复仍服从主设计§7.2：未提交新增引用不得外泄，已提交截面不可原地改写。

## 9. 进入整体评审前的具名判据

| 场景 | 必须成立 | 必须拒绝 |
| --- | --- | --- |
| d/r同事件 | 保存d后等待截面与r后完成截面，二者known_at可相同 | 只凭事件号读取C.latest |
| 右窗口边界后同事件继续 | 冻结问题继续读原窗口截面 | 用最终生命周期否定／补授旧截面 |
| 同D两项同时获证 | 实际按位置连接两个状态转移 | 两项都从同一旧游标消费 |
| 起点晚到 | 按规则选择补历史结构或检查KnownBy，真实事件不倒填 | 旧UTC等同旧已知事件 |
| 截止I/J | E=8无支持；E=9只有J；I最早10 | 分别取边际最早时间 |
| 有效Z覆盖 | 在明确不读旧z的活动域投影，旧Q保留旧截面 | 待首返时提前覆盖lastZ |
| 权限交接同事件 | 结果取决于来源与作用截面，不取决于回调顺序 | 瞬时Active决定永久历史结论 |
| 恢复 | 全管线恢复到同一提交事件，截面引用与支持同步 | 只恢复几何，留下未提交资格或冻结引用 |

以上为设计反例和判据，不是已执行测试。其覆盖必须加入整体D03/D04/D05/D06审查，不能沿用旧局部reviewer结论称本轮已通过。
