## 1. 目标与固定约束

目标是在现有 Rust L0 之上实现 F2，并从业务生成规则及增量执行结构上防止组合爆炸。目标不因某个局部模块可运行而缩小为中枢演示、固定三项切块或仅有接口的包装。

1. 数据主体使用 `Vec` 顺序存储；对象之间使用稳定下标，允许用不同类型包装下标以避免误用。
2. 不引入对象键、执行键、复合键、哈希值身份或全局哈希去重框架。不同历史共用后续时，直接引用已经存在的节点下标。

### 3.1 三项入口与游标转移

以下下标均相对一条已经获得连续性与相容性支持的直属材料序列，使用零基下标；材料的全局存储下标另行引用。设直属材料为 m，中枢级别为 H，材料级别为 H−1。W(s) 是 m[s]、m[s+1]、m[s+2]。检查前要求三项均已完成、同级、端点按顺序连接，并满足类型／位置角色合同。

| 入口 | 首次检查位置 | 材料不足 | 确定不成枢 | 成枢后 |
| --- | --- | --- | --- | --- |
| 根初始 | W(0)，根端点等于 m[0] 起点 | 等待到第三项 | 记录本窗口拒绝；不授结构或完成 | 发布局部中枢；可登记整体结构可能，不完成 |
| 一项进入兄弟 | W(1)，唯一左邻 m[0] 从同一根开始且与 m[1] 合法连接 | 等待到第四项 | 记录本固定窗口拒绝 | 建另一解释，保留原合法解释；不将任意 s>1 称一项进入 |
| 普通后枢 | 旧枢由 m[r] 首返完成，首次 s=r | 等待 m[s+2] | s 加一，新增一项后检查一次 | 采用首次成立目标并停止本搜索；保存前独立枢及其冻结离开前缀 |
| 完成枢共享 | 离开 m[d]、首返 m[d+1]，唯一 W(d−1) | 等待必要证据 | 本次共享读法拒绝，不后移 | 建有来源局部读法；不继承另一解释的整体资格 |
| 严格分离重组 | 最后有效 Z 为 m[z]，唯一 W(z) | 等待紧邻反向与下一同向项 | 若已严格离核仍不重叠，记录具名未覆盖；不后移、不自动退休 | 建新局部解释并显式交接旧活动职责 |

普通后枢成功时，只在当前尚无高级枢、前相关枢已完成、前后核心严格分离且外围相触／重叠的条件下，另保留 s+1 搜索分支。这是受限工程重组，不等同36课全部下级重新分解。普通成功目标仍保留，不能无条件以右移目标替换它。

完成枢共享还必须独立核验 m[d−1] 确实是旧枢最后有效同向 Z，不能只验证第二、第三项等于离开和首返。旧实现局部谓词未充分显式表达这一前提，Rust 设计按当前业务规则补足。

这些入口共享窗口计算，不自动共享其所属走势资格。认定窗口属于指定走势内部时，须先通过§3.4的材料归属与形成角色检查；不能先成枢再等趋势分类补验。角色缺证也不等于几何不重叠，不能据此触发搜索游标的“不成枢”前移。R4下独立合格的局部事实仍可继续推进。

严格分离重组等待时，若下一同向项触及原核心，则按实际覆盖恢复开放推进；若严格离核，才对固定三项判定重组。盘整在组合中的方向角色来自位置合同，不能用净位移为零否定其角色。

### 3.2 结构升级后的左段完成：R29-N 与 R32-P

本节给出两个明确区分的有限合同。R29-N引用[29课](../原文/chzhshch-108-plus/108/0456-486e105c010008la-029.md)“原级趋势背驰后最后中枢扩展”；R32-P引用[32课](../原文/chzhshch-108-plus/108/0467-486e105c010008vo-032.md)“下一中枢长成更高级别，a+A+b转为a′”。二者不能互相删改前提。固定H分段、三类点或高级存在标签本身均不授普通完成。

#### 3.2.1 共同的来源与依赖

证据绑定原解释I、目标解释J、实际左对象L及其root资格、切点e、右结构R的级别／形成依据／精确起点／owned来源、左I→J对应及右producer来源→J对应（来自固定D时为D/I_D→J）。e必须同时是L.end与R.origin，比较实际来源位置，不只比较价格。R全部owned来源位于e右侧；确认依据可以晚到，但不得并入L。R的生产者必须独立于本次L普通完成，否则依赖成环，保持待证。

高级精确核心不是左P/T分类公式的输入；右结构的级别、origin及合法来源不可省。若获准生产者独立给出结构与来源证明，而精确核心仍缺独立数值证据，左完成消费者不额外读取该数值，高级几何消费者继续等待。已复核的F6-D→S06可一起给出结构与精确核心；未获准的计数或包络公式不属于获准生产者。

输入L是**完整区间的单枢／趋势结构资格及待完成对象**，不是预先完成的P/T。否则“需要完成证明才能发完成”只是在接口里隐藏循环。结构清单、来源归属和方向须有实际依据，不能以最后枚举值代替检查。

#### 3.2.2 R29-N：原级趋势背驰后的最后枢扩展

在I中有H级有向趋势结构 `X=s0+Z1+s1+…+ZN+sN`，N≥2；Z1…ZN是该解释完整的H级中枢清单，形成角色、来源和依次同向严格分离均成立，没有遗漏该解释已成立的更高级归属。原H级真实趋势背驰及最后背驰段来源已获证。低级背驰、局部盘背不代替该前提。

令B=ZN，`e=s(N−1).end=B.start`，冻结 `L=s0+Z1+s1+…+Z(N−1)+s(N−1)`。后续独立证明B所在右部发生29课所述最后枢扩展，并以来源映射重写 `X+后续=L+R`。转换保持L的owned区间、root和方向，逐个保持Z1…Z(N−1)的形成窗口、核心、范围、已有完成关系与归属；右部不向左吸收。

29课第11行的N范围和第25—26行的最后枢局部重写支持如下工程推导：N=2时L恰剩一个H枢，为H-P；N≥3时剩N−1≥2个原本依次同向严格分离的H枢，为同向H-T。完成权来自原文局部重写，分类来自实际保留下来的前缀。不能将任意旧T拼入局部P，不能借单枢论证授T完成。[48课](../原文/chzhshch-108-plus/108/0513-486e105c01000a1n-048.md)署名答复只补充趋势延伸的相应解释，不单独承担任意前缀替换定理。

该合同明确了T分支，但仍依赖真实原级背驰及具体右部生产者；不据此宣告完整c、一般G1或所有Local29实例已能生成。

#### 3.2.3 R32-P：独立高级右部完成单枢左段

在I中有获证root下的合法 `L=a+A+b`，A是L唯一归属的H级中枢，L没有已成立的更高级结构归属。本有限域内a、b是实际完成且级别低于H的连接走势（249-Bar场景均为H−1）；其实际来源、a的进入及b在形成后的连接／离开资格已成立，`e=b.end`。缺口、空a及其他更广连接须另有获准通道。右B从e开始，具有独立合法来源及 `level(B)>H` 的证明。依据32课第25行的重写，在J中保持L的owned区间、root和单枢归属，授L普通H-P完成；右B仍开放。[33课](../原文/chzhshch-108-plus/108/0469-486e105c010008x4-033.md)第25—28行给出该左段的具名历史范围。

本规则不要求原H级趋势背驰，不先等待完整c。b不背驰是原文说明B至少为H的一种充分情形；已有独立B>H证明时不再附加此门。A/B跨级外围严格分离不是32课这一重写的独立前提，不能把旧同级趋势门移植过来；实际 `a+A+b+B` 的连接／来源资格仍须核验，不能仅以B.level>A.level补造。

另一固定D的几何核不自动成为I中L的第二个所属中枢，反之亦然；归属按§3.4和实际转换检查。R32不从F6分段生成L的普通root，也不把FixedPComplete转成普通完成。R32-T不在本条内：把低级a换成任意已有趋势，仍需独立前缀与完成推导。

#### 3.2.4 冻结、首次事件与交付

在实际左离开边界冻结L、e、比较域和已有资格；右证据只消费切点匹配的请求。若某个左移构造将旧左侧材料纳入右B，B.origin已改变，不能用它完成旧切点的L。证据晚到时读冻结版本，不要求活动游标退回某个p+9，不改读最新B状态。

每份证明的known_at取完整相容依赖的最大事件；同一事实的首次时间取各完整证明结果的最小值，禁止逐项借不相容证据。成功只发布所选J中L的普通完成及右开放结构关系；同端点旧S不自动获权，右B不因此成为普通完整同级后继。未知观察前缀、晚首枢和固定H起点不从本规则自动取得普通root。

旧Local29的 `m[0..p)` 左前缀、`m[p..p+9)` 右九项及p+9事件保留为**具体问题的冻结合同**：在该边界保存真实有序来源、A完成关系、B当时的外围／开放事实和缺项；后到证据引用它。它不是R29/R32的普遍计数触发条件。原0/1首枢、A/B同级外围严格分离等旧实例限制，只有在使用该实例的生产者时才适用，不用它们删改上述原文的其他合法域。

### 3.3 待评审补充：晚首枢发现

### 3.4 有限角色合同

以下合同落实总表 B08、C01—C10 和18课三种离开／返回组合，并对照旧工程 `F2Facts`、`F2Centers`、`F2MovementEnds` 的谓词。旧实现是核对来源，不替代本次评审。

必须区分三个量：材料自身净方向、它在固定连续序列中的形成／连接位置、相对固定核心的离开侧。完成盘整 P 的净方向可上、下或零；L0 与趋势必须有方向。零净位移不等于未完成，也不自动产生两条解释。

| 判定 | 可执行合同 |
| --- | --- |
| 相邻材料连接 | 已完成、同级、前末端等于后起点，且来源相容；若任一项是 P，不以二者净方向相同而拒绝；否则两项方向必须相反 |
| 三项几何重叠 | 上述连续连接加三项全范围共同交集非空；几何结果可共享，但不单独授予所属走势成枢资格 |
| 局部成枢 | 三项材料层级、完成、来源与局部形成角色均有依据；位置0、2为形成位置，位置1为连接位置。后续每消费一项翻转位置，不从 P 的净方向反推位置；独立局部事实不自动属于任意指定整体 |
| 带方向的角色要求 D | D 只能为上或下；非 P 材料方向必须等于 D；P 可以承担已被具体组合要求的 D，但须满足该组合的其余条件。未有消费者要求时不把 P 自动分叉为上／下两份 |
| 指定有向走势内的中枢归属 | 已明确向上走势／过程时，形成角色依次要求下、上、下；向下镜像。三项必须属于该解释下相应走势的材料范围，或由获证合法重组转入。认定该归属前就检查，不等走势完成或类型定为趋势 |
| 方向或归属尚未获证 | 保存具体缺项；不授指定整体的成枢、结构分类或完成权。R4下有独立依据的局部中枢继续推进，既不因未知整体起点全局等待，也不借其局部资格消除归属缺项 |
| 向上离开 | 材料为上向非 P 或完成 P；末端价 > ZG，且起点价 ≤ ZG 或前一材料触核。离开侧取“上”，不取 P 的净方向；向下镜像 |
| 离开后的候选首返 | 只检查紧邻下一完整材料，不跳过它等待后面的材料；必须再次检查级别、端点、类型连接及相容来源 |
| 非 P 离开＋非 P 首返 | 首返方向与离开方向相反；L0 按相同反向基元口径 |
| 非 P 离开＋P 首返 | 类型组合允许；仍须核验首返全范围及相容来源 |
| P 离开＋非 P 首返 | 首返必须逆实际离开侧：向上离开对应下向首返，向下离开对应上向首返；不能逆 P 自身净方向来替代 |
| P 离开＋P 首返 | 不授普通严格破坏；仍按触核／重组等适用条件处理，不能跳过这个 P 再补考 |
| 严格分离 | 类型与角色先通过，再要求向上离开后的首返全范围最低价 > ZG；向下为最高价 < ZD。相等不成立 |

形成材料不得兼任形成后的离开。形成位置的材料只有触核时才能扩大中枢外围；反向连接材料计入适用连续覆盖，但不自行扩大外围。待首返或待重组时，新材料触核仍可能构成新的实际离开；须重新按离开谓词判断并保存实际离开侧。P 的新离开可以与旧离开同侧，不能只检查反侧，也不能一律恢复为无待决事项的开放状态。

该表只定义规则请求时的有限角色，不授新的根、普通完成或任意跨解释连接。相同 P 可在不同合法组合中承担不同角色；仅在后续行为确有差别时保留不同角色槽。

### 3.5 新边界不必公开旧整体的精确起点

[27课](../原文/chzhshch-108-plus/108/0449-486e105c010008h4-027.md)、[29课](../原文/chzhshch-108-plus/108/0456-486e105c010008la-029.md)与[43课](../原文/chzhshch-108-plus/108/0499-486e105c010009mm-043.md)的终止消费者需要真实本级趋势及其尾部资格，并不在计算中强制读取旧起点坐标。这里接受一个有限接口推导：若已有封闭联合证书，证明在具名相容来源α下存在某个旧起点s，其H趋势以指定A/B为连续末枢、b/c角色及完整c均成立、整体创新极值与真实H背驰已获证，则可以消去s，只授予该终止规则实际允许的后继边界e。

不能先取“存在一个趋势”和“存在一个完成c”两个独立边际，再声称它们属于同一个旧整体。共同存在变量须在联合条件内消去，事件时间也从同一完整证据计算。结果保留α及实际新边界支持，不反造旧整体的精确左端、完整范围或父级普通材料，也不向全部祖先传播起点。

旧根坐标可以省，旧根曾承载的有效信息不能一起丢掉。37课所需整体新高／新低，必须有真实整体范围、足以判定的保守界或获证的来源截断依据；不能默认B的外围或当前可见端点已包含未知旧前缀的极值。

这修正了“未输出旧root就一票否决新边界”的过强接口。U06仍须给出从R4有限尾部**生成上述封闭资格**的业务充分式；将它命名为TrendTail或存一个存在标志不完成生成证明，也不把任意两枢几何直接升级为共同趋势。

## 5. 通过已有下标共享，不建立键驱动的合并器

### 5.1 生成位置拥有唯一的结果槽

一个业务生成位置保存它已产生的结果下标，例如：一个合法三项窗口保存成枢结果，一个中枢保存它的指定重组检查结果，一个冻结问题保存它的已获证完成结果，一个升级事实保存它的实际接收者。

重复触发直接读取该槽；新增支持追加到已有对象。这里的唯一性只针对相同生成位置及规则角色，不代表同端点的所有对象相同。

三项窗口必须由有序材料片段的相邻位置产生，并作为该片段的已有节点引用。多个生产者遇到同一窗口时，引用窗口已有的结果槽，不各自复制一个窗口后再进行全局去重。

对分支材料，邻接关系须由真实完成连接或合法转换建立；不得把所有端点相同的材料自由两两连接。角色不同且会影响消费者时，窗口保留分别的角色槽。槽的种类由规则枚举决定，不按历史路径动态增加一种槽。

### 5.2 历史汇合时共享哪些工作

业务交接必须显式携带接收者或共同片段的下标。不同历史引用同一接收者后，新材料只推进接收者一次，历史特有权限通过各自来源绑定访问。

局部计算和整体资格分开。例如，共用局部中枢的两段历史，一个整体起点获证、另一个未知，只运行一份中枢推进；完成请求分别判断起点资格。

不引入全局“扫描所有状态寻找相等者”的步骤。首次汇合通过以下具体的生成归属查找完成，而不是要求调用者预先知道共同节点。

## 7. 增量执行和同事件闭包

1. 验证并接收一个输入事件，确定新增材料、证据或权限变化。
2. 根据被修改对象已经保存的消费者下标，追加对应待执行工作。
3. 入队标记防止同一项工作重复排队；新版本差异决定实际需要处理的内容。
4. 执行消费者，写入新事实、支持、问题或交付；输出反向触发相关消费者。
5. 同事件继续处理到无新增工作，再提交本事件完整进度和发布增量。

### 7.1 新消费者订阅与已有事实追赶

创建消费者时，为其每项依赖记录“尚未读取”，登记到该依赖的消费者引用 Vec，并立即入队一次；不能等待依赖再次变化。首次运行直接读取已存在事实及当前版本，所以晚到来源转换建立的问题可以当场使用先前已到达的测量或完成依据。

消费时记录实际读取的依赖版本。读取期间新增的依赖也按“尚未读取”注册并触发追赶；本轮结束比较读到版本与依赖当前版本，仍有差异则保留待处理状态。单线程事件循环内，注册、入队和版本更新有确定顺序，不存在先清除标记再遗漏通知的间隙。

一个消费者的订阅列表不得因每条历史包装增加一份相同依赖。对象的消费者槽直接保存订阅下标；重复登记返回已有订阅。新消费者初次执行、依赖内容变化和实际新增交付是合法进展；重复通知、重复支持路径和无变化重排都不是进展。

一个工作被多次通知时须合并待处理影响，不能因为“已经排队”丢失后来依赖的变化。已执行后再有真正的新证据时允许重入队。重复发现同一事实或同一支持本身不构成进展。

每个规则实例的触发、消费位置和结果槽都在所属对象中。历史问题不参与全量轮询；只有新直属材料、起点证据、完成依据、来源转换、测量覆盖或接收状态改变时被唤醒。

没有新增 L0 的事件仍可能补足 MACD 覆盖或完成来源。普通完成的父级交付和高级接收是两条不同通道；它们产生的新工作均须纳入同事件闭包。

终止要求：不重复创建同一生成位置的对象；不以证据包装自己的循环产生新依据；升层必须消耗真实较低级材料并有无循环来源。有限输入不等于已经证明有限工作，规则评审须给出对应进展与有限性论证。

### 7.2 提交、暂停与失败恢复协议

一个外部输入事件是业务提交单元。分别保存：输入已接收位置、各阶段已消费位置、本事件工作队列位置、最后业务提交事件和已发布增量范围。已接收不等于已提交；外部查询只读取提交位置以内的结果。

正常运行时不复制全量状态。F2 对新增对象使用追加区域；对本事件修改的已有对象，首次修改时保存一份前值，并在对象中记录对应撤销记录下标。提交前读取旧状态时使用这份前值，新追加区域不可见。规则执行只在完整操作边界让出控制，避免暴露写到一半的前提或结论。

闭包完成后，统一推进各存储的提交边界及发布范围，再清除本事件撤销记录。发布者按提交日志范围读取增量；重读同一范围得到相同记录下标，不重新生成业务事实。外部消息系统的恰好一次投递不属于该内存引擎的隐含保证。

资源暂停发生在规则操作边界，保留当前事件、待执行队列、依赖版本及暂存修改；恢复时继续该队列，不把原 Bar 或原 L0 再交给上游。暂停期间明确返回“该事件尚未提交”，不能把暂存结果当成正式输出。

恢复工件包含输入日志、规则／数据版本、已提交检查点及发布位置。检查点持久化采用完整写入后再切换有效标记；没有完成标记的检查点不可用。进程中断后，从最近有效检查点按日志恢复到最后提交事件；未提交事件重新执行一次。恢复路径允许重放，生产每事件路径不允许借此全量重算。检查点频率是存储策略，不是业务历史截断。

F1 当前 API 不提供增量撤销。因此若 F1 返回已经推进 morphology 的错误，组合驱动必须将本事件标为上游失败，禁止继续喂新输入，禁止将返回状态当成可重投原 Bar 的完整旧状态。驱动从已提交检查点和输入日志恢复原提交位置；原因未解除时不自动重试失败事件。更改边界前提或修订历史输入须另立数据／规则版本。F2 不补造缺失 L0 绕过该错误。

F2 在事件内发生内部不变量冲突或实际执行错误时，用本事件撤销记录恢复已有对象、截去未发布追加区域并撤销未提交入队变化；下标只有在从未对外发布的暂存区才允许回收。错误原因与输入事件保留在诊断记录中。缺证、规则未覆盖或某组依据不相容是正常业务结果；拒绝该组组合，不因合法解释并存而触发事务失败。

上述失败必须由组合驱动统一处理：无论错误发生在质量门、F1、MACD 还是 F2，只要本事件任一上游已推进而事件未提交，立即阻止下一输入；质量状态、F1、MACD、F2 以及全部阶段消费位置一起恢复到同一个最后提交事件。F2 的局部撤销不能被当作组合恢复已经完成。当前选择的协议是检查点加已提交日志恢复全部阶段；不混用“上游保留新状态、只重投下游”的另一套协议。恢复完成并处理失败原因前，不重投原 Bar、不接收下一事件。

## 8. 模块边界与现有 L0 接入

建议独立 `rust-f2` 库，依赖现有 `rust-l0`；模块按领域职责分为输入适配、模型存储、局部结构、重组、整体资格及完成、高级接收、固定 H、力度及定位、证据、增量驱动和输出。不建立通用规则 DSL、通用对象注册表或通用解析器框架。

正式 Bar 路径为质量门 → 新获准闭合 Bar → F1 与 MACD → 完成 L0 增量及测量覆盖 → F2。在这条路径中，只有 `GateAccepted.structure_material=Some(bar)` 才推进 F1 和 MACD；活动尾更新及闭合尾幂等重送不重复消费。冻结 L0 回放通过同一 F2 材料入口导入，保留独立数据版本与已声明的上游前提，并允许经独立校验的冻结 close 流补充测量覆盖；该第二入口只推进测量，不重喂 F1／L0。同一数值运行内，来自两个入口的测量状态须绑定同一实际数据源、初始化、数值版本及覆盖位置；冻结 L0 与补充 close 另核验对应来源。具体见数值合同，缺少对应关系或原始 close 时保持缺证。不同运行和两种运行方式分别验收。

当前接入合同：

- 外层保存市场、标的、正 `TimeDelta` 周期、价格单位、规则／数值版本和数据版本。绝对时间使用 `DateTime<Utc>`，保留负纪元日期与纳秒精度，不压成 Unix 秒。输入事件序号为 `u64`，稳定集合下标为 `usize`，递增均检查耗尽；三者不互相代用。
- `LowestMovement` 直接给出起终端点、`SegmentDirection`、`full_range`、`known_at`。类型本身表示完成 L0，不再携带 `level_ordinal`、`composition` 或 `direct_materials`；更高级走势另用自己的对象与权限。
- `F1PipelineDelta.segments[i]` 与 `lowest_movements[i]` 按发布顺序逐条对应。适配层核对批次数量及账本追加位置，保存来源线段下标；不得仅凭几何猜测来源。冻结 L0 输入必须声明来源账本或外部来源前提，不能冒称已现场核验 F1。
- 每条 L0 先满足 `is_valid`；相邻端点完全相同、方向交替、确认时间不回退。`market_order` 表示去包含 K 线位置，`open_time` 表示真实极值来源 Bar 时间；两者与原始 Bar 序号均不同。
- 当前 `full_range` 已由起终端点实际时间之间的原始 Bar 闭区间求高低价极值，包含两端 Bar；保留不足成笔及被包含合并消去的内部极值，排除终点以后才吸收到同一合并 K 的 Bar。F2 直接保存该范围，不退回端点包络或去包含 K 的范围。
- F1 初始化方向须明确为 Upward／Downward。前三笔冻结时无公共重叠会拒绝声明起点；追加行情不能修复这个起点，须另立合法边界及相应输入回放。首条 L0 发布时还核验 `root_point` 及边界获知时间。F1 的 `CompleteBoundary` 不向祖先授予 F2 起点、完成或升层资格。
- 当前管线在线段／L0 错误时保留已推进 morphology，仅恢复 segment／lowest。在尚未恢复、仍保留失败事件的质量状态时，不能直接重投原序号；换新序号重送闭合尾也只会得到无结构材料的幂等接收，不能补做失败的结构推进。组合驱动按§7.2恢复质量门、F1、MACD、F2和消费位置；原因解除后，从上一提交位置使用原失败事件序号重新执行未提交事件，不跳号。
- MACD 由相同闭合 Bar 增量驱动。F1 的 `raw` 只有时间、高低价及获知时间，没有 close；测量器须保留自己的 close／递推及覆盖账本。缺初始化或区间覆盖返回缺证。测量器不授予结构资格或普通完成。

### 8.1 与新输入一致的数值边界

F2 几何采用上述 L0 数值合同。本次选定[MACD数值子合同](F2MACD数值合同.md)，其初始化、递推、精确面积、表示范围、双入口及失败方式已通过独立范围复审。它是离散工程规格，不声称等于无限精度实数 EMA、旧整数 Q 结果或某个平台。规则表§7.4的 Q 基线仅解释旧结果，不量化新 f64 输入。

第一条 close 直接初始化快慢线，DIF／DEA／柱为正零。后续快线、慢线、DIF、DEA、柱分别按合同给出的精确有理表达式只舍入一次到 binary64，采用最近值、相等取偶和渐进下溢；保存的每一步状态仍是 f64。不能自行更换运算次序、近似系数或融合策略。

每个已确定的有限 f64 柱精确解码成 `2^-1074` 单位的整数；正、负面积分开精确累计和比较，不先转回 f64。以独立 Bar 数不超过 u64 上限为条件，34个u64肢足以保存累计量。选定分块精确前缀加边缘逐柱求和：每次追加固定肢数工作，一次区间查询只读至多两个边缘块。它消除了简单 f64 前缀在 `2^53` 后吞掉增量1的问题；该算术反例不是已完成的实际 Bar 可达性证明。

两端 Bar 都纳入，共享端点在各自区间分别计算，面积不除以 Bar 数；初始化至测量末端的覆盖不足时保持缺证。有限输入不保证所有递推输出均可表示，溢出是明确数值失败，按§7.2全阶段恢复，不能转成“不背驰”。精确面积可以大于最大 f64，仍是可比较的有效整数。

专题已给常量、精确小数、首轮舍入、最小次正规数及面积层金标。开始实现前还须固定与真实结构对象对应的 E2E 场景、金标和失败方式；数值子合同通过不补完整 c 资格、不关闭 U02，也不代表已经运行 F2。

## 9. 资源目标及不可隐去的边界

首要验收条件：

1. 没有业务依据的分叉和普通完成交付为零。
2. 同一局部规则实例的执行次数不随完整解释路径数增长。
3. 不同历史汇入已有接收者后，共同后续和来源后缀只构造一份。
4. 增量推进只处理实际受影响工作；代价不包含无依据的全历史扫描。

设一个专门构造的场景有 R 份历史支持，共用长度 T 的后续，且这些历史对相应消费者确实等价：该场景的支持存储及共同执行应随 R+T 增长，不能按 R×T 复制。如果存在 K 种真实不同的未来资格，须分开量化这 K 种必要工作。

这不是所有行情的线性承诺。不同合法材料流、真实整体对象和相关支持的规模仍须分析；当前 U08 未提供全局多项式证明。不得把依赖匹配、相容检查或来源序列化中的乘法藏到未计数辅助函数中。

测量项包括：新增材料／结构／问题数，实际窗口检查数，实际消费者执行数，来源绑定数，支持节点及边数，等待关系数，公开增量字节数，内存和耗时。计数同时包含失败匹配及共享查找成本。MACD 另计柱数、区间查询数、边缘扫描柱数及固定肢工作；单次查询的常数界不能隐去结构消费者发起大量不同查询的总成本。

资源不足时停止消费并保留恢复位置，结果明确标记尚未完成处理；不得以资源限制删除合法解释。该机制不能代替正常规模下可实用性的验收。

## 14. 与根目录并行设计的比较与吸收

比较对象是原根目录 `F2设计方案.md`。比较发生在上述第二轮评审结论收齐之后；“评审完成”不代表“评审通过”。用户随后要求只保留本方案，原根目录稿已删除。以下保留吸收结果及取舍依据，不再维护第二份设计。

### 14.1 吸收的思路及本方案落点

| 并行稿思路 | 本方案采用方式 |
| --- | --- |
| E1—E6 将放大原因分别列为分叉、重复执行、证据复制、越权升层、全历史扫描、失败补考 | 采用这一排查分类，同时增加 E7 相容条件／时间函数自身增长；不声称六类已穷尽 |
| 每份新增来源先区分新事实、新支持、新角色或重复执行 | 每个生产者的增量收据分别计数前三类；重复执行不产生业务记录，且单独计入浪费诊断 |
| 依赖种类使用有限枚举并与订阅一致 | 各消费者声明材料、结构、起点／完成证据、来源转换、测量覆盖、接收状态等事件；注册时立即追赶，规则版本变更另开运行 |
| 共享透明性与同前缀重放一致性作为门禁 | 在小域独立参照中比较全部业务投影；长域使用正式 E2E 检查实际工作及来源增长，不以生产影子全量重算冒充增量成本 |
| 本级推进、冻结证据、高级接收分开盘点 | 每项职责保存自己的等待／完成状态；一项停止不能销毁另外两项 |
| 原文实例同时保存正结论和“不能据此声称”的限制 | E2E 金标同时检验应成立事实及禁止授予的权限，避免仅检验有输出 |

新增的 E7 尤其重要：共享事实节点后，来源条件图或 known_at 汇总仍可能指数增长。第二轮评审的多组相关选择反例须纳入设计分析，不以对象数量下降代替证据成本下降。

### 14.2 不吸收的做法及原因

1. 不引入 `ObjectKey`、`ContinuationKey` 或哈希共享池，遵守用户确定的 Vec／下标模型。
2. 不按完整解释谱系各复制一份父级材料账本。保留合法来源与顺序条件，实际材料与共同片段使用共享下标；否则来源汇合后仍会复制后缀。
3. 不在每个共享事实发布时遍历全部历史各追加一份绑定。并行稿这一操作仍会产生 R×T 证据量，与其防爆目标冲突；本方案要求共享支持容器和推导引用。
4. 不把起点权限及全部冻结问题放入统一几何执行状态。它们需要分别授权，但不应迫使共同局部中枢重复计算。也不以“状态宁可过宽”为性能免责理由。
5. 不接受“调度均摊 O(1)／事件”“证据 O(F+H)”“高级材料必按几何级数递减”及“瓶颈只可能在 L1”的未证断言。一次事件可能唤醒多个真实消费者，支持关系和高级解释也可能增加。
6. 不按共享前沿整体撤销所有历史权限。共同计算可能共享，历史支持的失效条件仍须分别核验。
7. 不先建单解释执行器再在下一阶段补共享调度。首次正式局部推进就使用同一套 Vec 存储、增量消费者和共同后续引用。
8. 不用随机性质测试代替正式 E2E 和规则充分性论证；抽样共享透明不能证明遗漏的状态字段永远无关。

### 14.3 比较后仍未解除的阻塞

并行稿没有提供消费者等价的完整业务证明，也没有解决重复相关选择的条件图规模问题。其来源逐历史绑定还暴露了一个额外乘法路径。因此吸收排查方法、依赖分类和验收组织，但不能据此把当前设计改成“已通过”。下一步继续收敛逐消费者状态／转移、有限角色合同以及已批准规则实际可生成的相关性；没有通过前不写代码。
